# 麦芽田退款同步规则

## 数据与去重

订单详情 `/order/detail/?detail=1&f=json&id=订单ID` 提供原商品数量、退款标记和履约状态，`fee.user_fee` 为顾客原实付，单位是分。退款详情 `/cancel/detail/?f=json&id=订单ID` 提供退款流水，`total_price` 单位是元，表示退给顾客的实付金额；`goods_format` 是 JSON 字符串。接口沿用系统配置的麦芽田 Cookie。

按 `source_cancel_id` 分组，使用每个请求的最新流水：存在数字流水 ID 时按 ID 判断先后，否则采用接口返回顺序。只有最新状态为 `1`、且没有撤销或拒绝标记的请求计入退款。申请与确认只计一次，不同请求的已确认金额累计。缺少请求 ID 的记录按一组保守处理。

## 订单与商品状态

退款商品优先按 `order_goods_id` 对应原商品行，再用原 SKU ID、货号或商品 ID 匹配。对照原数量、已退款数量，以及退款金额与原实付识别退款性质。商品的 `part_refund_title`（例如“已退款2件”）也可作为数量依据。

部分退款不因 `is_cancel: 1` 变成整单取消，继续展示实际配送或完成状态。全额退款或明确全部商品退款归入整单退款；部分退款不能触发整单自动回库。商品退款数量与实际退货入库记录分别处理。

## 美团到手与佣金

```text
剩余实付 = max(0, 顾客原实付 - 已确认退款累计金额)
平台佣金 = 剩余实付 × 6%，四舍五入到分
商家到手 = 剩余实付 - 平台佣金
```

原实付保留用于展示和退款性质判断。金额展示、订单利润和统计使用重算后的到手与佣金，不再从到手重复扣退款。退款不额外开放手动到手编辑，历史手动金额也不覆盖美团退款重算结果。原有抖店和线下金额编辑规则保留，其他平台不套用美团的 6% 佣金。

示例：原实付 ¥661.10，确认退款 ¥264.40，商品退 2/5 件。剩余实付 ¥396.70，佣金 ¥23.80，到手 ¥372.90；订单仍按履约信息展示“配送中”。

卡片实付展示退款后的剩余金额，并单列“已退”金额。商品退款标签悬停读取麦芽田已确认退款的原因和该次退款总金额（多商品退款时不冒充单个商品的退款金额），浮层通过 Portal 展示，避免被卡片裁切。

订单商品原数量保留用于核对；出库解析、库存不足提示、FIFO 扣库存均使用原数量减已退款数量。5 件退 2 件只出库 3 件，已全退商品不进入出库匹配。手动匹配总数量按剩余商品比例缩减，套餐内部每份数量和每份配件数量保留。

单笔订单同步按钮重新读取两个详情接口，返回修正后的履约状态、退款金额、到手和佣金，随后页面强制刷新列表。同步能重新判定误取消状态；既有库存退货记录仍需依据实际履约核对。
