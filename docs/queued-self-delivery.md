# 拣货后自动自配

普通平台订单未完成拣货时，原“自配”入口显示“拣货后自配”。点击后保存等待任务，再次点击“取消自动自配”可撤销。已完成拣货的订单仍可直接自配。预约单、线下单、自提单、已结束/退款/异常订单及已有配送任务的订单不会自动发起自配。

服务端启动时及每 30 秒检查等待任务，先同步平台状态，再确认完成拣货，复用原自配和自动完成流程。任务单独持久保存，不依赖浏览器保持打开，也不会被平台订单同步覆盖。多实例通过数据库条件更新抢占任务；结果不确定或进程中断的执行任务不会自动重发，页面会提示检查。

## 上线

1. 在目标数据库执行 [数据库迁移](../prisma/manual-migrations/20261019_add_queued_self_delivery.sql)，新增可空 JSONB 字段和状态索引。
2. 重新生成 Prisma 客户端、构建并重启服务。项目的构建和启动脚本已有 Prisma 客户端生成步骤。
3. 用测试订单标记等待任务，确认平台拣货完成后仅发起一次自配。也检查取消标记和预约单拦截。

迁移必须在运行新代码之前完成；无需回填历史订单。原订单利润和刷单标记只有实际自配成功后才变化。

## 本地逻辑验证

```sh
node scripts/queued-self-delivery.test.js
node node_modules/typescript/bin/tsc --noEmit --incremental false
```

自动化测试模拟平台响应和数据库状态，不会向实际订单发送命令。
